## 一、公开 GitHub 前的检查

1. **确认公开范围。** 仓库只包含项目源码、必要资源、文档和测试。排除个人学习记录、导出文件、浏览器个人资料、Cookie、账号凭据、令牌、私钥、支付资料和本机调试截图。检查 Git 历史，删除工作区文件不会自动移除历史中的秘密。
2. **核查权利。** MIT 授权仅覆盖有权授权的项目内容。第三方代码、字体、图片应保留各自许可证和署名。图标须核对源文件和来源，避免以 B 站官方标志暗示官方身份。
3. **保持可复现。** README 应说明最低浏览器版本、安装与使用方法、数据保存方式、已知限制、反馈入口和测试范围。构建后检查 ZIP 根目录能直接看到 `manifest.json`，再从该 ZIP 解压加载，避免只测试开发目录。
4. **先验证再标记版本。** 当前原生浏览器及真实 B 站验证尚待完成。若需要先分享，应明确标为候选版或预发布，说明具体未验证项目；完成这些检查后再决定稳定版标签。
5. **发布和维护。** 推送后检查公开页面、许可证、文档链接和下载包；Release 记录版本、改动、已知限制、测试范围及 SHA-256。收集问题时仅要求复现步骤、浏览器版本及脱敏截图，避免要求用户公开个人档案或 Cookie。

## 三、安装包和图片素材

### 安装包

- 使用项目打包脚本生成的商店 ZIP，包含运行必需的本地脚本、页面、样式和图标。
- `manifest.json` 位于 ZIP **根目录**，不要在外面额外套一层项目文件夹。
- 商店包不需要包含测试、个人记录、开发依赖或 Git 数据；源码仓库可以保留必要的开发资料。
- 当前使用 `manifest_version: 3`，后续更新应提高 `version`。不要通过远程脚本或下载代码绕过审核。
- 最低 Chrome 版本为 120。Edge 应用目标版本须实际测试，不能仅凭 Chromium 内核就宣称所有版本兼容。

来源：[Chrome 打包准备](https://developer.chrome.com/docs/webstore/prepare)、[Chrome Manifest 版本要求](https://developer.chrome.com/docs/extensions/reference/manifest/manifest-version)、[Edge 发布流程](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension)。微软已于 2026 年 8 月开始推动普通用户从 MV2 迁移至 MV3，见 [官方迁移公告](https://blogs.windows.com/msedgedev/2026/08/07/moving-the-microsoft-edge-extensions-ecosystem-forward-with-manifest-version-3/)。

## 四、权限与隐私：按当前代码填写

### 单一用途

可用于两店审核表单的草稿：

> 帮助用户在 B 站完成自己选择的学习任务：通过视频与 UP 主白名单、可自行开始和结束的专注会话，以及保存在本机的学习记录，减少无关浏览并回顾学习过程。

相关功能应围绕这一用途表述。不要增加“监控他人”“无法绕过”“保证提高成绩”“准确测量注意力”等当前实现无法支持的承诺。

### 当前 manifest 权限说明草稿

| 权限 / 配置 | 可提交的用途说明 |
| --- | --- |
| `storage` | 在当前浏览器配置的本地扩展存储中保存用户设置、视频/UP 主白名单、当前专注会话及学习记录；支持本地查看、清除及导出，不使用云同步。候选版本将此存储限制为受信任扩展上下文。 |
| `alarms` | 在后台安排倒计时到期处理，并在正计时会话中定期维护状态；用于恢复普通浏览和会话状态管理。浏览器关闭或后台调度延迟的边界须结合实际测试说明。 |
| `activeTab` | 用户主动点击扩展弹窗中的添加按钮时，读取当前活动页的 URL 和标题以校验并添加 B 站视频或 UP 主；无关站点不加入名单，不读取浏览器历史数据库。 |
| `declarativeNetRequestWithHostAccess` | 专注模式启用时，对 B 站顶层页面导航应用动态放行和重定向规则，使白名单视频、允许的 UP 主视频目录及必要登录页按规则访问，其余 B 站页面进入专注提示或验证页；结束会话时移除相应规则。 |
| `*://*.bilibili.com/*`、`*://bilibili.com/*` | 将上述导航规则限定到 B 站域名；内容脚本实际匹配 `www.bilibili.com` 和 `space.bilibili.com`。UP 主授权验证会向固定的 `api.bilibili.com` 视频信息接口提交 BV，获取所属 UP 主信息。 |
| `web_accessible_resources` 中的 `<all_urls>` | 让导航规则可打开包内 `blocked.html` 和 `gate.html`。这项是扩展资源的可访问来源匹配，**不等于为所有网站申请读取权限**。它的范围仍需审查；只有在原生 DNR 重定向、外站到 B 站导航、验证页及返回路径完成兼容测试后，才决定能否缩小为 B 站来源。 |

提交前将后台自动列出的权限与这张表逐项核对。若某项不再使用，应从代码与 manifest 一并移除并回归验证；不要为了将来可能增加的功能提前申请权限。涉及域名或资源范围的改动需要相应原生浏览器测试。

来源：[Chrome 隐私表单、单一用途与最小权限](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy)、[Edge 隐私资料要求](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension#step-6-enter-privacy-information)。

### 数据处理披露草稿

下列内容应与仓库 [PRIVACY.md](../PRIVACY.md)、实际代码和商店勾选保持一致。**仅在本机处理也需要披露**，不能以没有开发者服务器为由填写“完全不处理用户数据”。Chrome 明确把网页内容、访问的 URL、用户输入内容等纳入用户数据范围，见 [用户数据政策 FAQ 第 3、4、6、14 项](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)。

> BiliFocus 将设置、白名单和学习记录保存在当前浏览器配置的 `chrome.storage.local` 中，不提供开发者账号、服务器、云同步、广告、遥测或 AI 调用。
>
> 扩展处理用户主动输入的视频 BV、UP 主 UID/名称、计时设置；在学习会话中处理允许视频的标题、BV、分 P、可见 UP 主信息、会话起止时间、播放观察时间和采样播放用时。临时的标签页/文档标识与媒体位置用于避免重复计算，不进入最终记录和导出。
>
> 用户主动添加当前页面时，扩展读取活动页 URL 和标题以进行名单校验。UP 主授权需要向 B 站固定视频信息接口提交相应 BV，请求显式不携带 Cookie 或登录凭据；B 站仍会收到该 BV 和 IP 等正常网络信息。学习记录本身不会发送到开发者服务器或分析服务。
>
> 扩展不读取密码、Cookie、B 站账号历史接口或无关浏览历史。记录可在扩展学习空间中查看、导出和清除；在会话结束后输入确认文字可删除已保存的历史，白名单保留。档案最多保留 300 次会话，并受约 4 MB 预算限制，必要时按最旧记录淘汰。单会话最多保存 500 个不同视频/分 P 条目，后续播放仍计入总量并显示提示。
>
> 导出的 Markdown/JSON 含个人学习与观看信息，由用户自行保管；卸载可能清除本地数据，应提前导出。本版本没有导入界面。采样播放用时不等于注意力、理解程度或学习成果。

商店数据类别应依据后台现有选项逐项核对，重点关注网站内容、浏览活动和用户提供的内容，并明确其本地处理方式。不要声称“不与任何第三方通信”：UP 主校验确实会请求 B 站接口。远程代码字段如实际保持当前实现，可说明所有扩展执行脚本都随包提供，固定接口仅返回用于校验的数据，未下载并执行远程代码。

隐私政策 URL 应公开、稳定、无需登录且能直接阅读。可在公开仓库基础上设置专门网页或 GitHub Pages；**仓库已推送不代表 Pages 已启用**。填表前用退出登录的窗口打开该 URL，确认内容和版本准确。

## 五、商店文案草稿

以下文案是候选稿。完成真实验证和素材核查后，再按最终功能与支持范围修改并提交。

### 名称与简短介绍

名称：**BiliFocus | B 站学习专注助手**

简短介绍：

> 为 B 站自选课程设置视频与 UP 主白名单，使用正计时或倒计时开展专注学习，在本机保存并导出学习记录。

如最终 manifest 名称不同，应统一修改，避免包内名称、仓库名称和商店描述相互冲突。建议分类为浏览器后台提供的“生产力 / Productivity”或最接近的学习工具类别。

### 详细介绍

> BiliFocus 是面向 B 站课程学习的浏览器扩展。你可以先选择想学的视频或 UP 主，再开始一次专注会话，让页面访问围绕自己的学习名单展开。
>
> 主要功能：
> - 通过 BV 或视频链接建立白名单，也可以添加 UP 主 UID 或空间链接。
> - 在正计时与倒计时之间选择；学习会话由你主动开始和结束。
> - 专注期间按名单放行视频与 UP 主视频目录，对其他 B 站页面显示提示或进行授权校验。
> - 通过页面上的入口打开独立学习空间，管理设置和回顾记录。
> - 在本机保存会话及视频/分 P 的采样播放记录，支持每日 Markdown 摘要与 JSON 导出。
> - 时间数字平时收起，悬停或键盘聚焦时显示，减少反复看表的干扰。
>
> 数据与边界：
> 设置和学习记录保存在当前浏览器配置的本地存储中。扩展没有开发者服务器、广告、遥测、云同步或 AI 调用；UP 主授权验证会向 B 站固定接口发送对应视频 BV，且不携带 Cookie 或登录凭据。
>
> 这是一项自愿使用的专注辅助工具。用户可以结束会话或停用扩展。采样播放时间用于个人回顾，不能证明注意力、理解或学习成果。B 站页面结构、播放器和接口变化可能影响兼容性；请参考项目说明中的当前支持范围和已知限制。
>
> BiliFocus 是独立开发的第三方项目，与哔哩哔哩 / Bilibili 无隶属、赞助或官方合作关系。相关名称与商标归各自权利人所有。
>
> 问题反馈：https://github.com/xiac1300-create/bilifocus/issues

第三方身份声明不能替代素材授权核查；仅在所述身份和授权事实真实时保留。不要在商店名称、图片或介绍中添加“官方”“B 站认证”等未经证实的字样。

## 六、供审核人员使用的测试说明草稿

**下列步骤须先由发布者在真实浏览器和真实 B 站完成一遍。当前待验证，不能提交为已完成记录。** 不向审核人员提供个人 B 站账号、Cookie、个人历史档案或 GitHub 令牌。若后续确有受限功能需要测试账号，应使用专门测试账号，并通过商店的私密审核字段提供。

1. 在全新的浏览器测试配置中安装，打开扩展弹窗和学习空间，确认默认没有正在进行的会话。
2. 选一个当时可公开播放且无需付费的普通 B 站视频，使用其 BV 加入视频白名单。测试说明中填入本次实际使用的完整视频 URL，勿预先编造有效链接。
3. 开始正计时，打开白名单视频并播放。检查时间默认收起，悬停和键盘聚焦时显示；移出后收起。通过页面入口打开学习空间，确认原会话继续。
4. 访问一个未加入名单的 B 站普通页面，确认出现预期提示；返回白名单视频。结束会话，检查本地记录可见，并核对采样播放用时的合理性。
5. 开始 1 分钟倒计时，检查到期结束和普通浏览恢复；结合后台暂时休眠及浏览器重新打开情形核查恢复边界。
6. 添加一个实际 UP 主 UID，检查其视频目录及该 UP 主视频授权。再测试不同 UP 主的视频，以及接口超时、断网或失败时的提示和访问限制。
7. 检查多分 P、站内切换视频、刷新页面和多标签页时的记录与去重行为。
8. 在学习空间导出每日 Markdown 和全部 JSON。确认临时内部标识未进入导出；会话结束后按确认流程清除历史，并确认白名单仍在。
9. 在 Chrome 和 Edge 分别复测导航规则、扩展页打开及上述核心流程，记录完整浏览器版本、日期、通过项与失败项。

审核备注可简写为：

> 使用扩展弹窗进入学习空间，添加测试视频的 BV 后开始正计时或 1 分钟倒计时，再访问相应 B 站视频。该扩展不要求开发者账号。请使用可公开播放的普通视频；特定 B 站内容的登录、地区或付费限制由该网站决定。学习记录仅在本地保存，可在学习空间查看和导出。测试视频 URL、浏览器版本及当前已知限制见本次提交附注。

## 七、实际提交顺序

### Chrome Web Store

1. 注册开发者、完成账号与两步验证，查看当时实际注册费并自行付款。
2. 在开发者后台选择新增项目，上传核对过的 ZIP。
3. 填写商店介绍、语言、分类、支持入口，上传图标、宣传图及真实截图。
4. 填写单一用途、每项权限理由、远程代码与数据处理披露，提供公开隐私政策 URL。
5. 选择分发地区及 Public / Unlisted / Private。小范围链接测试可以使用 Unlisted；仍须通过审核。
6. 填写审核测试说明。确认是否审核后自动发布；如需自行控制公开时机，取消自动发布选项。
7. 提交审核，保存提交版本和反馈。通过后在选择的方式下发布，获取真实商店安装链接，再更新 GitHub README 和 Release。

官方步骤：[发布到 Chrome Web Store](https://developer.chrome.com/docs/webstore/publish)。

### Microsoft Edge Add-ons

1. 注册或进入 Partner Center 的 Edge 计划，个人项目按实际身份选择账号类型；注册后国家/地区和账号类型不能随意更改。
2. 新建扩展并上传 ZIP，检查从 manifest 自动读取的名称和说明。
3. 在 Availability 选择市场和 Public / Hidden；在 Properties 选择分类与支持信息。
4. 填写 Privacy 中的用途、权限、远程代码、数据处理和隐私政策。
5. 为每种发布语言填写商店资料和必需 Logo，上传真实功能截图。
6. 填写认证测试说明，核对后提交认证。通过后检查真实安装链接，再更新 GitHub 资料。

官方步骤：[发布 Microsoft Edge 扩展](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension)。

## 八、每次更新都要复查

- 提高 manifest 版本号；文档、打包名称、Release 标签保持一致。
- 有权限或数据处理变化时同步修改隐私政策和商店披露，再测试受影响流程。
- 包内所有执行逻辑保持可审核；若加入 AI、云端保存、统计或第三方服务，先重新评估数据流和用户告知。
- B 站页面或接口变化可能使旧功能失效；问题未验证修复时，在已知限制中如实说明。
- 保存提交记录、测试结果和下载包校验值，发布后用普通用户视角检查安装与更新。

仅在实际完成后勾选本文清单。发布结果应分别记录 GitHub 仓库、候选下载包、商店待审和正式上架状态。
